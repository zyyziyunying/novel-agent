# 版本管理

更新日期：2026-10-12。本文件维护软件版本、变更记录与 Git 标签规则；产品范围和推进计划由 [SPEC.md](../SPEC.md) 维护，已实现变更由 [CHANGELOG.md](../CHANGELOG.md) 登记。

## 软件版本来源

根目录 [VERSION](../VERSION) 是软件版本的唯一维护来源。根 workspace、`agent`、`viewer` 和 `novel_contracts` 使用同一版本，各 `pubspec.yaml` 的 `version` 是同步副本。包在本地共同交付，暂不分别发布。

当前版本以 VERSION 为准；0.1.0 是首个本地原型基线，0.2.0 是 SPEC 中的下一阶段目标。开发下一版本期间保留当前基线版本，将已实现且验证过的后续变更写入 CHANGELOG 的 `Unreleased`；计划本身留在 SPEC。

版本采用 `主版本.次版本.补丁版本`：

| 变更 | 递增规则 | 本项目示例 |
| --- | --- | --- |
| 已有能力的兼容修复、维护 | 补丁版本 | `0.1.0` → `0.1.1` |
| 新增可验收功能；在 0.x 阶段引入不兼容契约时也必须说明兼容影响 | 次版本 | `0.1.x` → `0.2.0` |
| 稳定发布后破坏已承诺的兼容性 | 主版本 | `1.x.y` → `2.0.0` |

0.x 为原型阶段，尚未承诺稳定 API；不兼容变更仍须登记影响与数据处理方式。需要预发布时使用 `-alpha.N`、`-beta.N` 或 `-rc.N`，N 为非负整数，各数字不得有前导零。本阶段不使用 `+build`；需要追踪具体开发构建时记录 Git commit。

## 检查与同步

在仓库根目录运行；工具仅依赖 Dart SDK：

```sh
dart run tool/version.dart --check
```

检查 VERSION 格式、四个 `pubspec.yaml` 的一致性，以及 CHANGELOG 中唯一的 `Unreleased` 和当前版本日期条目。失败返回非零退出码；检查模式不改文件。

升版时先修改 VERSION 并整理当前版本的 CHANGELOG 条目，再同步包版本：

```sh
dart run tool/version.dart --sync
dart run tool/version.dart --check
```

`--sync` 先验证所有输入，再只更新各 `pubspec.yaml` 的版本字段；不修改 CHANGELOG、依赖版本或数据文件。新增 workspace 包时，同时将其加入工具的检查列表。当前工具为本地执行入口，尚未接入 CI。

## 软件版本与数据版本

| 标识 | 负责什么 | 当前机制 |
| --- | --- | --- |
| VERSION / 包版本 | 软件基线与交付范围 | 统一管理 |
| `schemaVersion` | 持久化 JSON 格式是否可读 | 默认多作品服务及工作台为 2，独立原型为 1；各自拒绝其他版本，不迁移 |
| 工作区 `revision` | 并发提交与旧请求冲突 | 每次成功提交递增 |
| 正文 `versionId` / `head` | 正文历史及当前版本 | 内容变化生成新版本，恢复时切换指针 |
| 记忆 `sourceHeads` | 派生记忆与正文是否一致 | 全部章节版本匹配才可用 |

运行时机制的权威说明见 [架构说明](architecture.md)。软件升版不自动增加 `schemaVersion`，也不改作品修订号或正文历史。数据格式发生变化时，单独说明格式版本、兼容范围与数据处理方式，并在 CHANGELOG 登记；需要保留已有数据时再设计迁移、备份与失败恢复。本轮的数据处理前提与新格式接入按 SPEC 推进。

## 基线与发布登记

0.1.0 本次只登记本地原型基线。CHANGELOG 中的日期表示基线登记或后续版本完成日期；Git 标签用来标识实际完成验证并提交的代码。

完成后续版本时依次执行：

1. 核对 SPEC 对应验收项；将实际实现与限制更新到 SPEC 和架构说明，已完成的计划阶段补充验证依据。
2. 将 `Unreleased` 中已实现的条目归入目标版本，填写 Asia/Shanghai 日期；保留新的 `Unreleased`。记录契约和数据兼容影响，链接验证依据。
3. 修改 VERSION，执行同步与检查；按 [README](../README.md#验证) 运行项目检查。真实接口烟测、模拟测试与写作质量评测分别记录。
4. 将该版本的代码、版本文件与文档纳入同一发布提交，确认工作区干净。正式版本使用注释标签 `vX.Y.Z`；预发布使用 `vX.Y.Z-rc.N` 等同名标签。已有标签保持不变，修复另发版本。

首次完成 0.1.0 发布登记后，可在已验证的发布提交上执行：

```sh
git tag -a v0.1.0 -m 'Novel Agent Lab 0.1.0'
```

标签应与该提交的 VERSION 和 CHANGELOG 对应。推送标签、远程部署或对外发布按实际交付任务执行；本次文档与机制建立没有执行这些操作。
