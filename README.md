# Novel Agent Lab

面向小说作者的知识库与写作工作台。作者主导创作，Agent 辅助续写和改稿。采用 Flutter Web、Dart Agent、Genkit Dart 1.0.0 与 DeepSeek 插件。工作台已接入格式 2 多作品、独立知识库、资料版本采用与持续讨论；[外部工具写入流程](docs/external-write.md) 已完成工程验收，整体验收与发布按 [SPEC](SPEC.md#020-推进计划) 推进。

软件版本以 [VERSION](VERSION) 为准，当前登记基线保持 0.1.0；0.2.0 尚未发布。版本规则见 [版本管理](docs/versioning.md)，已实现变更见 [CHANGELOG](CHANGELOG.md)，实现边界见 [架构说明](docs/architecture.md#m5-持续讨论与作者选择采用成果)。

## 本地运行

已验证工具环境：Flutter 3.44.1、Dart 3.12.1。Genkit 相关依赖固定为 1.0.0，根目录提交 `pubspec.lock`。

在仓库根目录安装依赖：

```sh
flutter pub get
```

终端一，在仓库根目录启动服务。无 API 密钥时仍可管理作品、保存已有正文与资料：

```sh
dart run agent/bin/novel_agent.dart
```

要演示首章起草、选段改稿与记忆闭环，显式启用固定演示模型：

```sh
dart run agent/bin/novel_agent.dart --fixture
```

终端二启动工作台：

```sh
cd viewer
flutter run -d web-server --web-hostname localhost --web-port 4300
```

打开 `http://localhost:4300`，填写 Agent 启动时显示的**工作台会话令牌**。Agent 地址默认 `http://127.0.0.1:4100`。令牌只保存在页面内存中，刷新页面后重新填写。

首次启动创建空 `library-workspace.json`，在界面创建并命名作品，再通过“新建章节”开始手写，或让模型起草第一章。新服务不读取或迁移旧 `workspace.json`。已有格式 2 数据重启后继续读取；损坏、旧格式或未知格式会拒绝启动，不会静默重置。

真实 DeepSeek 模式：在终端一设置 `DEEPSEEK_API_KEY`，然后运行默认入口。默认模型为 `deepseek-flash`，通过 `DEEPSEEK_MODEL` 切换。供应商密钥仅在 Agent 中读取；本地配置放在 `.local/`。示例字段见 [.env.example](.env.example)，程序读取进程环境，不会自动加载该文件。

已在本机配置 `.local/deepseek.env` 时，可直接启动：

```sh
tool/run_deepseek.sh
```

该脚本默认使用 `.local/deepseek-data` 并启动格式 2 服务，端口仍为 `4100`。格式 1 独立入口 `agent/bin/prototype_agent.dart` 保留用于原型回归，不兼容当前工作台。两个入口共享目录锁；同时运行时指定不同目录与端口。

| 环境变量 | 默认值／用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 真实模型必需；无密钥仍可运行非模型操作 |
| `DEEPSEEK_MODEL` | `deepseek-flash` |
| `NOVEL_AGENT_PORT` | `4100`，仅绑定本机回环地址 |
| `NOVEL_VIEWER_ORIGIN` | `http://localhost:4300`，精确匹配浏览器来源 |
| `NOVEL_DATA_DIR` | 根目录启动时为 `.local/novel-data` |

## 体验闭环

1. 创建两部具名作品。点击“新建章节”（窄屏为章节选择旁的加号），填写标题后进入空白正文，手写并“保存正文”；无需模型。也可由模型起草第一章并接受提案。空白章节先填写保存，重建记忆后可起草下一章；作品 B 的正文与提案独立。
2. 在两部作品中交替编辑并切换，未保存草稿、选区与章节选择保留。页面刷新不恢复未保存草稿；已经保存的作品、名称与正文可在服务重启后读取。
3. 在已保存正文中选段改稿，查看前后全文与生成上下文后接受或拒绝。选段外内容由宿主保留，拒绝不会改变正文。
4. 改动旧章后，后续章待作者复查，原文保留。修订或确认复查，再重建记忆；记忆失效或仍有待复查章节时不能续写。
5. 从“历史版本”恢复正文；版本按本章历史显示为“第 1 版、第 2 版……”，恢复后保留原序号，继续保存追加新版本。手动创建时的空白正文为第 1 版。匹配当前全部章节版本的历史记忆可重新使用，否则显式重建。

保存或生成期间可以切换作品；响应、失败与重试始终属于发起作品，后台状态可点击返回查看。保存等待期间继续输入的正文仍保留。结果未知时刷新核对回执，或用原请求重试；有未确认结果时其他写入会被拒绝。刷新冲突保留草稿，作者可查看后放弃草稿并加载新版本。

点击顶部“管理知识库”，可独立创建／命名知识库、新增或编辑设定、参考和计划，并填写结构化原始来源。创建作品不是管理资料的前提；这些操作无需模型。选择作品后先关联知识库，再逐份采用最新版或在历史中选择指定版本；同一知识库可供多作品引用。发布新版会提示“有新版可采用”，各作品的旧引用保持不变。停止采用或取消关联保留资料历史。返回正文时，页面内草稿、选区和章节选择保留。

提案的“查看修改与上下文”可核对资料身份、采用版本、写入者和原始来源；历史提案沿用生成时的清单。作品改用其他资料版本后，旧提案接受会提示冲突。资料更新、采用、参考或计划的新增都不直接改变正文或派生记忆。编辑冲突时保留草稿；作者可查看后明确放弃草稿并加载最新版。结果未知时用原请求重试或刷新确认回执。演示模型输出固定样稿，只用于交互验证。

点击顶部“持续讨论”，新建具名作品讨论或关联章节，连续发送问题并回看每轮记录。输入草稿按作品和讨论保留在当前页面；每轮可展开查看所用正文历史版本、资料身份、采用版本与来源。讨论建议不会自动改变正文、设定或记忆。

选择一条作者消息或助手回复，可“保存到知识库”，明确选择目标库与参考／设定／计划身份；保存后仍需在知识库中采用资料版本。也可“生成改稿提案”，选择同作品目标章，在原文中选中替换片段，编辑替换文本，再保存待接受提案；返回正文查看前后文与讨论来源，接受或拒绝。来源正文或采用资料变化时提示冲突，成果内容保持在表单中。

讨论失败或中断时，查看本轮状态并“重试本轮”；该操作使用原请求、原作者消息和原来源。来源已变化时发起新一轮讨论。结果未知时先刷新或重试原请求，pending 回执只表示作者消息已保存，不表示回复已完成；刷新确认 completed 后迟到网络失败不会重置状态。服务重启将未完成轮次标为 interrupted，等待显式重试。无模型时可回看已有讨论、创建讨论、保存成果或生成改稿提案，发送新一轮需配置模型。

## 本地 HTTP

会话令牌用于 `GET /libraryWorkspace` 与 `POST /libraryAction`。响应报告模型配置状态，模型是否配置不影响资料保存。作品和正文操作、资料协议及结果结构见 [架构说明](docs/architecture.md#m2-新格式持久化与启动)。

创建作品的例子；`$NOVEL_SESSION_TOKEN` 是本次启动的会话令牌：

```sh
curl http://127.0.0.1:4100/libraryAction \
  -H "Authorization: Bearer $NOVEL_SESSION_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"data":{"apiVersion":2,"requestId":"create-first-work","expectedRevision":0,"target":{"kind":"catalog"},"operation":"createWork","payload":{"id":"first-work","title":"第一部作品"}}}'
```

资料服务支持创建／命名知识库以及追加资料版本，不调用模型。提交时使用当前 revision、明确目标、未使用的请求 ID；更新资料需匹配预期 head，并使用新版本 ID。结果未知时保留原请求，服务优先检查已提交回执。资料写入不自动采用到作品；`setKnowledgeLinks` 以作品为目标，提交完整关联库清单及各库的资料 ID → 版本 ID 映射（空映射仅关联）。版本必须存在；取消采用与关联也通过该操作提交。讨论与成果采用已开放；外部工具新增／更新资料、来源字段、冲突与原请求重试说明及可运行 JSON 示例见 [外部工具写入资料](docs/external-write.md)。外部保存后通过工作台顶部“刷新作品”查看资料与历史。

## 验证

仓库根目录：

```sh
dart run tool/version.dart --check
dart analyze
dart test agent/test packages/novel_contracts/test
```

工作台目录：

```sh
flutter test --no-pub
flutter build web --no-pub
```

Agent／契约测试覆盖格式 2、持久化、无模型 HTTP、事务去重、多作品正文隔离、记忆与版本冲突，讨论三轮与失败重试、SIGKILL 后恢复及成果采用，以及格式 1 原型回归和 Genkit DeepSeek 模拟 HTTP。外部写入验收直接提交文档 JSON 示例，覆盖工具／原始来源、鉴权、版本冲突、失败恢复与重启复用。工作台测试覆盖单作品编辑行为、多作品切换与草稿、迟到响应、知识库管理、固定版本采用、来源展示、冲突编辑和窄屏交互，以及讨论三轮交互、切换输入、成果采用、待完成回执和迟到响应；外部写入后的刷新组件测试核对原目标、来源、选择与固定采用版本。

历史固定虚构样例的三项 [真实 DeepSeek 接口烟测](docs/research/2026-10-10-deepseek-live-smoke.md) 使用格式 1 原型；M3–M5 新流程由工程测试与演示模型验证，本轮未执行真实接口调用；新讨论真实接口烟测留待 M7 发布验收。中文成稿质量与实际成本仍待正式评测。
